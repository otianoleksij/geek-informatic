# Як додати завдання

Посібник для вчителя й автора контенту. Програмувати не треба: усе робиться правкою текстових JSON-файлів у теці `content/`. Для розробників є окремий посібник: [`how-to-add-activity.md`](how-to-add-activity.md).

Усі приклади нижче перевірені: їх вставляли у копію репозиторію, і валідатори та `build-pages --check` пройшли без помилок.

## 1. Спершу прочитайте це

1. **JSON дуже прискіпливий до коми й лапок.** Між елементами списку кома є, після останнього її немає. Лапки лише прямі `"`. Усередині тексту можна писати «ялинки», “лапки” й апостроф ’ (він у файлах скрізь саме такий), але прямі `"` усередині тексту потрібно екранувати: `\"`.
2. **`id` рівня, ребуса чи завдання пишуть латиницею малими літерами через дефіс** (`kebab-case`): `two-crystals`, а не `Two Crystals` і не `два_кристали`. Ребуси: `r` і три цифри (`r101`).
3. **Старий `id` ніколи не міняйте.** Прогрес учнів у браузері зберігається саме за `id`, і за ним же будуються посилання на кшталт `games/robot/#turn`. Змінили `id` означає, що в усіх учнів цей рівень знову стане непройденим, а старі посилання зламаються. Тексти, карти й розв'язки міняти можна.
4. **Жирний текст** позначається так: `**слово**`. Інакше форматувати не можна. HTML-теги (`<b>`, `<br>`, `&nbsp;`) заборонені.
5. **Двомовність.** Робот і Код Галактики мають тексти `{"uk": "…", "en": "…"}`: потрібні обидві мови. Ребуси лише українські. Квест КіберЩиту має окремий файл для кожної мови (`uk.json`, `en.json`), і правки вносять в обидва.
6. **Кількість елементів вільна.** Можна додавати скільки завгодно рівнів робота й Галактики, ребусів (у кожній групі хоч один) і завдань у місіях КіберЩиту. Єдиний виняток: **КіберЩит має рівно 8 місій** (це константа гри: 8 літер секретного слова й 8 іконок). Числа «10 рівнів», «100 ребусів» тощо на головній, на сторінках вчителів і приватності та в описах сайт бере з вашого JSON автоматично, але для цього після правки треба один раз запустити `node tools/build-pages.js` (розділ 3).
7. Після правки **завжди запускайте валідатор** (розділ 3) або дочекайтеся зеленої галочки CI на GitHub (розділ 2).

## 2. Як редагувати без встановлення програм (github.com)

1. Відкрийте файл у репозиторії на github.com, наприклад `content/robot/levels.json`.
2. Натисніть значок олівця (**Edit this file**) праворуч угорі.
3. Внесіть правку. Редактор не перевіряє JSON, тож стежте за комами й лапками.
4. Натисніть **Commit changes…**. Якщо в репозиторії немає права запису, GitHub сам створить копію (fork) і запропонує відкрити pull request. Якщо право є, оберіть **Create a new branch … and start a pull request**, щоб не зламати робочий сайт.
5. Відкрийте pull request. Унизу сторінки з'явиться перевірка **check**. Вона запускає всі валідатори (`tools/check-*.js`, `build-pages --check`):
   - зелена галочка: все гаразд;
   - червоний хрестик: натисніть **Details**, відкрийте крок **Validators** і прочитайте повідомлення. Вони такі самі, як у розділі 3.
6. Виправте файл тією ж кнопкою олівця в тій самій гілці. Перевірка запуститься знову.
7. Коли галочка зелена, натисніть **Merge pull request**. Сайт оновиться за хвилину-дві.

Те саме можна робити у VS Code: правте файл, запускайте перевірку в терміналі, потім commit і push. CI на GitHub запускається на кожен push і pull request.

## 3. Як перевірити й подивитися результат на своєму комп'ютері

Потрібні Node.js і Python 3 (на macOS Python вже є).

1. У теці репозиторію запустіть валідатор потрібної гри (команди в розділах нижче). Успіх закінчується рядком `OK`, помилки виводяться списком, код виходу 1.
2. Додатково `node tools/check-schemas.js` перевіряє структуру (зайві або відсутні поля, неправильний `id`) у всіх JSON одразу. Він швидкий і ловить синтаксичні помилки JSON.
3. Щоб побачити гру: `python3 -m http.server`, потім відкрийте `http://localhost:8000/`. Подвійний клік по `index.html` (`file://`) не працює, бо гра читає JSON через `fetch()`.
4. Прямі адреси: `http://localhost:8000/games/robot/#two-crystals`, `…/games/kod-galaktyky/#big-ring`, `…/puzzles/rebusy/#r101`. Англійська версія має префікс `en/`: `http://localhost:8000/en/games/robot/`. Посилання з `#id` відкриває рівень навіть закритий.
5. Після правки JSON оновіть сторінку з очищенням кешу (`Cmd+Shift+R` або `Ctrl+Shift+R`).

**Після додавання або видалення рівня, ребуса, місії запустіть `node tools/build-pages.js`.** Сама гра читає JSON під час роботи, а от кількості («11 рівнів», «101 ребус») вписані в згенеровані сторінки: головну, `teachers/`, `privacy/` і мета-описи. Якщо їх не оновити, CI на GitHub покаже червоний хрестик на кроці `build-pages --check` зі списком застарілих файлів (`Застарілі сторінки (запусти node tools/build-pages.js)`). Правки тексту чи карти існуючого елемента (без зміни кількості) збірки не потребують. Без Node на комп'ютері (лише github.com) попросіть колегу з Node запустити команду на вашій гілці й закомітити результат або скористайтеся GitHub Codespaces.

Кількості беруться з `content/…` через поле `count` запису активності в `catalog.json` (див. [`how-to-add-activity.md`](how-to-add-activity.md), розділ 2). Українські слова відмінюються автоматично (`11 рівнів`, `21 рівень`, `2 рівні`).

Картинка для соцмереж ребусів (`assets/og/rebusy.png`) містить напис «100 ребусів»: це PNG, його оновлює розробник (`python3 tools/og/make.py rebusy`).

### Повідомлення, які можна побачити в будь-якій грі

| Повідомлення | Що це означає |
|---|---|
| `content/…json: Expected ',' or '}' after property value in JSON at position 5609` | Синтаксична помилка JSON: пропущена кома або лапка. Подивіться на місце біля вказаної позиції, часто це кінець попереднього рядка. |
| `… $.levels[10].id: «Two Crystals» не відповідає ^[a-z0-9]+(-[a-z0-9]+)*$` | `id` не у форматі kebab-case. `[10]` означає одинадцятий елемент списку (нумерація з нуля). |
| `… id «turn» повторюється` | Такий `id` уже є. Придумайте інший. |
| `… зайве поле tip` | У схемі такого поля немає: помилка в назві поля або воно з іншого типу завдань. |
| `… немає поля …` | Не вистачає обов'язкового поля. |

## 4. Робот (`content/robot/levels.json`)

Валідатор: `node tools/check-robot.js`. Читати рівні в грі: `games/robot/#<id>`.

### Приклад: новий рівень

Вставте в кінець списку `levels` (після попереднього рівня поставте кому, після цього не ставте):

```json
    {
      "id": "two-crystals",
      "title": {"uk": "Два кристали", "en": "Two crystals"},
      "tip": {"uk": "Збери спочатку верхній кристал, а потім повертайся за нижнім.",
              "en": "Collect the top crystal first, then come back for the bottom one."},
      "map": ["S.G", "...", "G.."],
      "maxBlocks": 8, "par": 6, "loops": false,
      "solution": ["R", "R", "L", "L", "D", "D"]
    }
```

### Що означають поля

| Поле | Значення |
|---|---|
| `id` | Унікальний kebab-case. За ним зберігається прогрес і будується `#id`. |
| `title` | Назва рівня, `uk` і `en`. |
| `tip` | Підказка на жовтому стікері, `uk` і `en`. |
| `map` | Поле: один рядок списку це один рядок карти. `S` старт (рівно один), `G` кристал (хоча б один), `#` камінь, `.` порожньо. Усі рядки однакової довжини. |
| `maxBlocks` | Скільки блоків дозволено поставити. Не менше, ніж у розв'язку. |
| `par` | Кількість блоків у вашому розв'язку. Учень отримає 3 зірки, якщо вклався в `par`, 2 зірки при `par`+2, інакше 1. **Має дорівнювати** кількості блоків у `solution`. |
| `loops` | `true`, якщо в рівні є блок «Повтори», інакше `false`. |
| `solution` | Ваш розв'язок: команди `"U"` вгору, `"D"` вниз, `"L"` ліворуч, `"R"` праворуч. Повтор записується так: `{"rep": 5, "body": ["R"]}` (число повторів від 2 до 5, вкладених повторів немає). Блоком вважається кожна команда й сам повтор. |

Правила підрахунку блоків: `["R","R","L"]` це 3 блоки, `[{"rep":5,"body":["R"]}, {"rep":5,"body":["D"]}]` це 4 блоки (повтор і стрілка всередині, двічі).

### Правила для рівня з повторами

Якщо `loops: true`, то `maxBlocks` має бути **меншим** за мінімальну кількість ходів без повторів. Інакше повтори будуть не потрібні. Валідатор показує мінімум у колонці «Мін.ходів».

### Типові помилки

| Повідомлення | Причина |
|---|---|
| `рівень two-crystals (11): par 5 ≠ блоків у розв'язку 6` | `par` не збігається з довжиною `solution`. |
| `… розв'язок не виграє: зібрано 1 з 2 кристалів, робот врізався в камінь або в край поля на кроці 6` | Крок 6 це шостий хід розгорнутої програми (повтор рахується за всі свої ходи). Інший варіант кінця повідомлення: `програма закінчилась раніше, ніж зібрано всі кристали`. |
| `… блоків у розв'язку 9 > maxBlocks 8` | `maxBlocks` менший за розв'язок. |
| `… поле не прямокутне (рядок 2)` | Рядок карти коротший чи довший за перший. |
| `… невідомий символ «X»` | У `map` дозволені лише `. # S G`. |
| `… стартів має бути 1, а є 0` | Немає `S` (або їх кілька). |
| `… немає title.en` | Не заповнено англійський текст. |
| `… розв'язок має повтор, а loops:false` | Поставте `"loops": true`. |
| `… для loops maxBlocks (…) має бути меншим за мін. ходів (…)` | Рівень з повторами надто «вільний»: зменште `maxBlocks`. |

### Додати новий рівень (11-й і далі)

1. Додайте рівень, як у прикладі, у кінець списку `levels`.
2. `node tools/check-robot.js` і `node tools/check-schemas.js`. Кількість рівнів перевірка не обмежує.
3. `node tools/build-pages.js`: на картці, на сторінці вчителів і в описах з'явиться «11 рівнів». Без цього CI зупиниться на `build-pages --check`.
4. Рядок з переліком `#id` рівнів в `i18n/*/teachers.json` (`links.robot`) є звичайним текстом: за потреби додайте туди новий `id` і знову запустіть `build-pages`.

Правка існуючого рівня (`title`, `tip`, `map`, `solution`, `par`, `maxBlocks`; `id` не чіпайте) збірки не потребує.

## 5. Код Галактики (`content/kod-galaktyky/levels.json`)

Валідатор: `node tools/check-galaxy.js`. **Працює повільно, приблизно 2 хвилини** (шукає мінімальну програму для кожного рівня). Це нормально, не переривайте. Для швидкої перевірки структури запускайте `node tools/check-schemas.js`.

Гра в `games/kod-galaktyky/#<id>`.

### Приклад: 16-й рівень (із вкладеними повторами)

```json
    {
      "id": "big-ring",
      "title": {"uk": "Велике кільце", "en": "The big ring"},
      "story": {"uk": "Навколо ангара лежить велике кільце з кристалів. Одна сторона — чотири кристали, і так чотири рази.",
                "en": "A big ring of crystals lies around the hangar. One side has four crystals, and there are four sides."},
      "tip": {"uk": "Одна сторона: «🔁 повторити 4 [вперед, зібрати]». Увесь обхід: повтори «сторона + поворот праворуч» чотири рази.",
              "en": "One side: “🔁 repeat 4 [forward, collect]”. The whole loop: repeat “side + turn right” four times."},
      "size": 8,
      "map": ["#......#", ".S****..", ".*##.*..", ".*##.*..", ".*##.*..", ".*****..", "........", "#......#"],
      "start": {"dir":"E"},
      "maxBlocks": 5, "par": 5,
      "allowed": ["F","L","R","C","rep"], "limits": {"C": 1},
      "solution": [{"rep": 4, "body": [{"rep": 4, "body": ["F","C"]}, "R"]}]
    }
```

### Що означають поля

| Поле | Значення |
|---|---|
| `id` | Унікальний kebab-case (за ним прогрес і `#id`). |
| `title`, `story`, `tip` | Назва, історія, підказка; `uk` і `en`. У текстах можна використовувати емодзі й «ялинки». |
| `size` | Сторона квадратного поля, від 6 до 9. Має збігатися з картою. |
| `map` | Рівно `size` рядків по `size` символів. `S` старт, `*` кристал, `#` астероїд, `.` порожньо. |
| `start.dir` | Куди дивиться корабель: `E` праворуч, `N` вгору, `W` ліворуч, `S` вниз. |
| `maxBlocks`, `par` | Ліміт блоків і «ідеальна» кількість (3 зірки). `par` дорівнює кількості блоків у `solution` і не більший за `maxBlocks`. |
| `allowed` | Які блоки є в палітрі: `F` вперед, `L` ліворуч, `R` праворуч, `C` зібрати кристал, `rep` повторити. |
| `limits` | Скільки разів можна використати блок: `{"C": 1}` (не більше одного «зібрати»), `{"R": 0}` (заборонено). Порожні `{}` дозволені. |
| `solution` | Розв'язок: рядки `"F"`, `"L"`, `"R"`, `"C"` і повтори `{"rep": 4, "body": [...]}`, число від 2 до 9, вкладення до 3 рівнів. |

Корабель летить у напрямку, куди дивиться, а повертає лише на місці. Кристал збирається блоком `C` на його клітинці. Рівень виграно, щойно зібрано всі кристали (наступні команди розв'язку не потрібні).

### Правила, що залежать від номера рівня

Валідатор вимагає різного залежно від позиції рівня в списку (повідомлення так і починаються: «з 4-го рівня потрібен повтор…»):

| Позиції | Вимога |
|---|---|
| 1–3 | Без повторів: в `allowed` немає `rep`, у розв'язку немає повторів. Запас `maxBlocks` над мінімумом (за BFS) не більший за 3. |
| 4 і далі | `rep` в `allowed`; розв'язок містить повтор; **без повторів рівень пройти за `maxBlocks` не можна**. |
| 10 і далі | Розв'язок містить **вкладений** повтор; немає розв'язку без вкладених повторів у межах `maxBlocks`. |
| увесь набір (від 10 рівнів) | Хоча б один рівень із глибиною вкладення 3 (зараз це «Серце станції»). |

Тому новий рівень, доданий у кінець (позиція 16 і далі), має бути «вкладеним» типу `big-ring` вище: кристалів багато, а `maxBlocks` малий. Вставляти рівень посередині не радимо: вимоги залежать від позиції.

### Типові помилки

| Повідомлення | Причина |
|---|---|
| `… карта не квадратна (8×7)` | Кількість рядків не дорівнює довжині рядка. |
| `… size 7 не збігається з картою або поза 6..9` | Поле `size` не відповідає карті. |
| `… розв'язок не виграє (статус …, зібрано 14/15)` | Розв'язок не збирає всі кристали. |
| `… розв'язок порушує обмеження: limit C` | Розв'язок використовує блок більше разів, ніж дозволяє `limits` (тут `C`); для заборонених блоків схоже повідомлення з іншим словом після двокрапки. |
| `… par 6 ≠ блоків у розв'язку 5` | `par` не збігається з розв'язком. |
| `… кристал (x,y) недосяжний` | Кристал відрізаний астероїдами. |
| `… з 4-го рівня потрібен повтор: без повторів рівень проходиться за N блоків, а maxBlocks M (…)` | Для рівнів 4+ має бути потрібен повтор: зменшіть `maxBlocks` або ускладніть карту. |
| `… з 10-го рівня вкладений повтор має бути потрібним: є розв'язок без вкладених повторів на N блоків, а maxBlocks M (…)` | Для рівнів 10+ потрібен вкладений повтор: ускладніть карту або зменшіть `maxBlocks`. |
| `… з 10-го рівня потрібен вкладений повтор (повтор у повторі), а в розв'язку його немає` | Рівні від 10-го мусять мати вкладений повтор. |
| `… рівні 1–3 навчають без повторів, тож у розв'язку не має бути повторів (повтори з 4-го рівня)` | Рівні 1–3 без `rep` (так само для `allowed`). |

### Додати новий рівень

1. Додайте рівень у кінець списку (позиція 16 і далі: вимоги для «вкладених» рівнів, див. вище).
2. `node tools/check-schemas.js` (швидко), потім `node tools/check-galaxy.js` (близько 2 хвилин). Кількість рівнів перевірка не обмежує.
3. `node tools/build-pages.js`, щоб оновити «16 рівнів» на картці, на сторінці вчителів, у `description` і підписі `tag` на сторінці гри.
4. За потреби додайте новий `id` у рядок `links.galaxy` в `i18n/*/teachers.json` і знову запустіть `build-pages`.

Вставляти рівень посередині не радимо: вимоги залежать від позиції, а порядок розблокування зміниться. **Безпечніше змінювати тексти й карту існуючих рівнів, не чіпаючи `id`.**

## 6. Ребуси (`content/rebusy/uk.json`)

Тільки українська (`uk.json`): ребуси тримаються на грі слів, тому для інших мов потрібен окремий набір, а не переклад. Валідатор: `node tools/check-rebuses.js`. Показ у грі: `puzzles/rebusy/#<id>`.

### Приклад ребуса

```json
    {"id":"r101","g":"7-9","answer":"ТОК","hint":"Рух електричних зарядів у проводі: без нього лампа не світиться.","parts":[{"pic":"🐯","w":"ТИГР","keep":[1]},{"pic":"🐺","w":"ВОВК","keep":[2]},{"pic":"🐱","w":"КІТ","keep":[1]}]}
```

Читається так: від «ТИГР» залишилась 1-ша літера `Т`, від «ВОВК» 2-га літера `О`, від «КІТ» 1-ша літера `К`; разом `ТОК`.

### Поля ребуса

| Поле | Значення |
|---|---|
| `id` | `r` і не менше трьох цифр (`r101`). Унікальний. |
| `g` | Група класів: `1-4`, `5-6`, `7-9` або `10-11` (список `groups` на початку файлу). |
| `answer` | Відповідь **великими українськими літерами**. Пробіли, дефіси й апострофи при перевірці ігноруються (`ОБ'ЄКТ` допустимо). Відповіді не повторюються. |
| `hint` | Підказка до 120 символів. **Не повинна містити слово відповіді**: для слів із 5 і більше літер там не може бути перших 4 літер відповіді, для коротших слів не може бути слова цілком. |
| `parts` | Від 2 до 4 частин, зліва направо. Серед них хоч одна картинка. |

### Частини ребуса (`parts`)

Кожна частина належить до одного з трьох видів:

| Вид | Приклад | Що дає |
|---|---|---|
| Звичайні літери | `{"t":"А"}` | літери `А` як є |
| Картинка | `{"pic":"🐭","w":"МИША","r":1}` | слово `w` (**великими літерами**), до якого застосовано операції (нижче). `pic` це рівно один емодзі |
| Число | `{"num":"100","w":"СТО","r":1}` | те саме, але замість картинки число |

Операції над словом `w` (виконуються у цьому порядку: `rev` → `keep` → `rep` → `l`/`r`):

| Ключ | Значення | Приклад |
|---|---|---|
| `rev: true` | прочитати слово навпаки | `{"pic":"🧀","w":"СИР","rev":true,"rep":[["И","У"]]}` дає `РУС` |
| `keep: [1,3]` | залишити літери з цими номерами у вказаному порядку | `{"pic":"🐸","w":"ЖАБА","keep":[1,2],"rep":[["Ж","Ф"]]}` дає `ФА` |
| `rep: [["Ж","Ф"]]` | замінити першу знайдену літеру `Ж` на `Ф` | |
| `l: 1` | кома зліва: прибрати стільки перших літер | `{"pic":"🏹","w":"ЛУК","l":1}` дає `УК` |
| `r: 2` | коми справа: прибрати стільки останніх літер | `{"pic":"🐼","w":"ПАНДА","rep":[["Н","П"]],"r":2}` |
| `x: [3]` (лише для `t`) | закреслити літеру з цим номером у `t` | `{"t":"НАР","x":[3]}` дає `НА` |

Не можна поєднувати `keep` із `l` чи `r`.

### Правила

- Відповідь має **збігатися з тим, що виходить із `parts`**. Валідатор сам обчислює слово тією ж функцією, що й сторінка.
- Не менше однієї картинки (`pic`), не лише число.
- Звичайних літер (`t`) має бути не більше приблизно 40% відповіді. Ребус має складатися здебільшого з картинок.
- **Емодзі.** Валідатор приймає лише емодзі зі списку `EMOJI_TABLE` у `tools/check-rebuses.js`: їх версія Emoji не вища за 11.0, тож вони відображаються на Windows 10 і Android 9 (новіші дадуть порожній квадратик). Див. розділ «Емодзі» нижче.
- Один рядок файлу відповідає одному ребусу; кома після кожного, крім останнього.

### Типові помилки

Повідомлення мають вигляд `r101: …` і підсумок `ПОМИЛКИ (N), id: …`.

| Повідомлення | Причина |
|---|---|
| `r101: відповідь ТІК ≠ обчислено ТОК` | `answer` не збігається з тим, що виходить із `parts`. Виправте відповідь або частини. |
| `r101: помилка в parts: keep: position 9 is outside the word "ТИГР"` | `keep` посилається на неіснуючу літеру. |
| `r101: помилка в parts: rep: "Ж" is not in "ТИГР"` | Заміна шукає літеру, якої немає у слові на цьому кроці (зверніть увагу на порядок `rev`, `keep`, `rep`, `l/r`). |
| `r101: помилка в parts: l/r removes too many letters …` | Прибрано всі літери або більше. |
| `r101: підказка містить слово/корінь відповіді («ток»)` | Перефразуйте підказку. |
| `r101: підказка задовга (…)` | Не більше 120 символів. |
| `r101: частина 1: pic має бути одним емодзі` | У `pic` більше одного емодзі. |
| `r101: частина 1: w має бути великими літерами` | Слово картинки пишуть великими українськими літерами. |
| `r101: невідома група 3-4` | `g` має бути одним із `groups`. |
| `r101: дублікат відповіді КОД (також r011)` | Така відповідь уже є в іншому ребусі. |
| `r101: завелика частка звичайних літер: 3/5` | Забагато `t`: замініть частину літер картинками. |
| `r101: немає жодної картинки` | Усі частини складаються лише з `t`. |
| `$.rebuses[100].id: «r12» не відповідає ^r[0-9]{3,}$` | Це повідомлення `check-schemas.js`: потрібно `r` і щонайменше 3 цифри. |
| `група 7-9 порожня: у ній немає жодного ребуса (додайте ребус або приберіть групу з groups)` | Кожна група з `groups` має мати хоч один ребус. Кількість ребусів загалом і в групі довільна. |
| `r101: емодзі «🦊» (U+1F98A) немає в таблиці EMOJI_TABLE. Перевірте його версію … ≤ 11.0 …` | Емодзі не у списку дозволених. Див. «Емодзі» нижче. |
| `r101: емодзі «👁» (U+1F441) має текстове відображення за замовчуванням: додайте після нього U+FE0F, …` | Для таких символів після емодзі потрібен невидимий знак U+FE0F (у таблиці вони записані з `\uFE0F`). Найпростіше скопіювати емодзі з існуючого ребуса. |
| `r101: емодзі «🐯️» має зайвий U+FE0F: …` | Навпаки: у цього емодзі FE0F зайвий. |
| `r101: емодзі … має версію Emoji 12.0 > 11.0 — на старих системах не відобразиться` | Запис у таблиці вказує на надто нову версію: оберіть інше емодзі. |

### Додати або замінити ребус

1. Додайте новий рядок у кінець списку `rebuses` (з комою після попереднього) у потрібній групі `g`, або видаліть старий ребус і вставте новий. Новий ребус отримує новий `id` (`r101`), тож у учнів він не буде «вже розгаданим». Кількість ребусів загалом і в групах не обмежена, групи мають бути непорожні.
2. `node tools/check-rebuses.js` і `node tools/check-schemas.js`.
3. `node tools/build-pages.js`: «100 ребусів» на головній, на сторінці приватності й в описах стане «101 ребус». Без цього CI зупиниться на `build-pages --check`.
4. Перегляньте `http://localhost:8000/puzzles/rebusy/#r101`.

Приклад перевірено: ребус `r101` (група `7-9`) додано в копію репозиторію; усі валідатори та `build-pages --check` пройшли, на головній написано «101 ребус».

### Емодзі в ребусах

Старі Windows 10 (до 1809) і Android 9 показують лише емодзі версії Emoji 11.0 і старше. Новіші дають квадратик, тож `tools/check-rebuses.js` приймає тільки емодзі з таблиці `EMOJI_TABLE` (там їх понад 50: тварини, їжа, предмети).

**Додати емодзі в таблицю:**

1. Дізнайтеся версію Emoji символа на emojipedia.org (рядок Emoji Version, наприклад `Emoji 3.0`) або в `emoji-test.txt` на unicode.org. Вона має бути не вище 11.0.
2. У `tools/check-rebuses.js` додайте запис у `EMOJI_TABLE`: `"🦊": "3.0"` (ключ це сам символ, значення це версія).
3. Якщо символ за замовчуванням малюється чорно-білим (як `👁`, `⚖`, `⛰`), у ключі після нього має стояти `\uFE0F`: `"👁\uFE0F": "0.7"`, і в `pic` у JSON цей знак теж має бути. Копіюйте такі емодзі з наявних ребусів.
4. Запустіть `node tools/check-rebuses.js`.

## 7. Агенти КіберЩиту (`content/agenty-kibershchytu/<мова>.json`)

Два файли: `uk.json` і `en.json`. Тексти там **окремі рядки для кожної мови** (не `{uk, en}`): вносьте правку в обидва файли з однаковими `id`. Валідатор: `node tools/check-kiber.js` (швидкий). Гра: `web-quests/agenty-kibershchytu/` (місії відкриваються по черзі, прямих адрес немає).

Будова: файл містить `word` (секретне слово) і `missions` (8 місій). Кожна місія має `id`, `title`, `letter` (одна літера секретного слова), `icon`, `intro`, `facts` і список `tasks` (мінімум 3). Кожне завдання має `id`, `type`, `q` (питання) та поля свого типу.

### Приклад: нове завдання в місію

Вставте після завдання `bank-sms` місії `phishing-trap`, у **обох** файлах. Українською:

```json
        {
          "id": "unknown-link",
          "type": "choice",
          "q": "Незнайомець у грі надіслав тобі посилання: «Тут безкоштовні кристали, швидко заходь!». Що зробиш?",
          "options": [
            {
              "text": "Одразу натисну: кристали ж безкоштовні",
              "correct": false
            },
            {
              "text": "Не натискатиму посилання і покажу повідомлення дорослим",
              "correct": true
            },
            {
              "text": "Перешлю посилання друзям, нехай теж отримають кристали",
              "correct": false
            }
          ],
          "explain": "Безкоштовні подарунки від незнайомців майже завжди пастка. Не натискай і покажи повідомлення дорослим."
        },
```

Англійською (у `en.json`, той самий `id`):

```json
        {
          "id": "unknown-link",
          "type": "choice",
          "q": "A stranger in a game sent you a link: “Free crystals here, hurry up!” What will you do?",
          "options": [
            {
              "text": "Click it right away: the crystals are free",
              "correct": false
            },
            {
              "text": "Not click the link and show the message to an adult",
              "correct": true
            },
            {
              "text": "Forward the link to friends so they get crystals too",
              "correct": false
            }
          ],
          "explain": "Free gifts from strangers are almost always a trap. Do not click, and show the message to an adult."
        },
```

Після цього в перевірці побачите `34 завдань, 101 балів` замість `33` і `100`: підсумок рахується автоматично, нічого ще міняти не треба.

### Типи завдань

Бал за завдання дорівнює: 1 для `choice`, `multi`, `password`; кількості рядків для `classify`; кількості ознак для `hotspots` і місць для `scene`; кількості слів для `wordsearch`; 2 для `order`; 3 для `memory`; кількості питань `ask` для `chat`; кількості налаштувань для `privacy`.

| `type` | Обов'язкові поля | Особливі правила |
|---|---|---|
| `choice` | `options`, `explain` | Від 2 варіантів, **рівно один** `"correct": true`. |
| `multi` | `options`, `explain` | Правильних від 1 до (кількість варіантів − 1). |
| `classify` | `labels` (2 підписи), `items`, `showAll` | Кожен рядок: `text`, `answer` (0 або 1), `explain`. Обидві категорії мають хоч один рядок. |
| `order` | `items`, `explain` | Від 2 різних кроків; **у файлі їх пишуть у правильному порядку**, гра сама перемішує. |
| `memory` | `pairs` | Пари `term`/`meaning`, усі тексти карток різні. |
| `wordsearch` | `size`, `alphabet`, `words` | Див. нижче. |
| `password`, `hotspots`, `privacy`, `chat`, `scene` | складні структури | Копіюйте існуюче завдання цього типу з файлу й змінюйте тексти. Для `scene` потрібен малюнок `scenes/<мова>/<picture>.svg` з атрибутами `data-spot` і `data-decoy`: це робота для того, хто вміє SVG. |

**Сітка пошуку слів (`wordsearch`)**:

- `size` від 5 до 14 (сітка `size`×`size`), `alphabet` це літери-наповнювач для порожніх клітинок (не менше 10 символів без пробілів).
- Кожне слово: `{"word": "ФІШИНГ", "row": 4, "col": 1, "dir": "h"}`. Нумерація рядків і стовпчиків із 0; `dir` це `h` (зліва направо) або `v` (згори вниз).
- Слово не може виходити за сітку, а спільні літери перетинів мають збігатися.
- Початок і кінець слова мають однозначно його визначати (учень натискає першу й останню літери).
- Слова не повторюються.

### Правила літер і секретного слова

- Кожна місія має `"letter"` рівно з одного символа.
- `word` має дорівнювати літерам усіх місій, складеним підряд (`ЗАХИСНИК` = З, А, Х, И, С, Н, И, К). Число літер = числу місій = 8.
- Літери і слово для кожної мови свої (в `en.json` слово `DEFENDER`). Гра сама перемішує літери для учня.
- Рівно 8 місій (змінити можна в `EXPECTED_MISSIONS` у `tools/check-kiber.js`, але сторінка й тексти теж розраховані на 8).

### Правила для рядків

- Жодного HTML (`<b>`, `&amp;`), порожніх рядків; розмітка `**…**` має бути парною.
- Усі `id` (місій, завдань, місць на сцені) у форматі kebab-case, а `id` завдань унікальні **в межах усього квесту**, не лише місії.
- `id` місії не може збігатися із зарезервованими адресами екранів (`map`, `final`, `cert`, `start`).

### Типові помилки

| Повідомлення | Причина |
|---|---|
| `… місія phishing-trap / unknown-link (choice): choice: має бути рівно 1 правильний варіант, а є 0` (або `є 2`) | У `choice` один правильний варіант. |
| `… id завдання не унікальний у квесті` (разом із `$.missions[1].tasks[3]: id «bank-sms» повторюється`) | Такий `id` вже є. |
| `… id має бути kebab-case латиницею` | `id` лише `a-z`, цифри, дефіси. |
| `… HTML у рядку: «Безкоштовні <b>подарунки</b>…»` | Приберіть теги; для жирного використовуйте `**…**`. |
| `… непарна розмітка ** у «…»` | Пропущені закривні `**`. |
| `… невідомий type «quiz»` | Допустимі типи наведені в таблиці вище. |
| `word «ЗАХИСНИК» ≠ літери місій «ЖАХИСНИК»` | Змінили `letter` місії і не змінили `word` (чи навпаки). |
| `… letter має бути однією літерою` | У `letter` більше одного символа. |
| `… слово «…» повторюється` / `… конфлікт літер у клітинці 3,4` / `… виходить за межі сітки 10×10` | Помилки у `wordsearch`. |
| `… початок і кінець не визначають слово однозначно` | Два слова мають однакові кінці. |
| `Unexpected …`/`Expected double-quoted property name in JSON at position …` | Синтаксис JSON (зайва кома в кінці списку тощо). |
| `потрібно рівно 8 місій` | Кількість місій у КіберЩиті стала (8 літер слова, 8 іконок). |
| `content/agenty-kibershchytu/en.json: місія «phishing-trap»: завдання [mail-triage, fake-site, bank-sms2, phishing-email] ≠ [mail-triage, fake-site, bank-sms, phishing-email] у uk.json (однакові id в тому самому порядку в усіх мовах)` | Файли мов розійшлися: завдання додали лише в одну мову або `id` різні. Подібні повідомлення: `місія №N: id «…», а в uk.json «…»`, `type «…», а в uk.json «…»`. Порядок місій і завдань, їхні `id` і `type` мають збігатися в усіх мовах (тексти, відповіді, літери та слово свої). |

### Нову місію додавати не можна

Місій рівно 8 (змістовна константа: 8 літер секретного слова, 8 іконок). Кількість **завдань** у місії вільна (мінімум 3): додавайте завдання в існуючі місії. Після додавання завдань запустіть `node tools/build-pages.js` не обов'язково (бали й завдання рахуються з JSON), але кількість місій на картці береться з `count`, тож вона не зміниться.
